## Part 1: Vibe Coding이란 무엇인가?

### 1.1 한 줄 요약

**Vibe Coding**은 코드를 직접 타이핑하는 대신, **자연어로 의도를 설명해서 AI가 코드를 작성하게 하는** 개발 방식입니다.

### 1.2 탄생 배경

2025년 초, OpenAI 공동 창립자이자 전 Tesla AI 총괄이었던 **Andrej Karpathy**가 이 개념을 공개적으로 언급하면서 큰 반향을 일으켰습니다. 그는 자신이 코드를 작성할 때 더 이상 문법을 신경 쓰지 않고, 자연어로 AI에게 "이런 느낌으로 만들어줘"라고 말하는 수준에 도달했다고 밝혔습니다.

여기서 **"Vibe"** 는 "분위기" 또는 "느낌"을 뜻합니다. 즉, 정확한 코드 문법 대신 **"이런 느낌의 코드를 원해"** 라고 AI에게 전달하는 방식입니다.

### 1.3 기존 코딩과의 비교

| 구분 | 전통적 코딩 | Vibe Coding |
|------|------------|-------------|
| **입력 방식** | 키보드로 코드 타이핑 | 자연어로 의도 설명 |
| **핵심 역량** | 문법, API 암기 | 의도 전달, 프롬프트 설계 |
| **수정 방식** | 코드 라인 단위 편집 | "이 부분을 더 간결하게 해줘" |
| **디버깅** | 에러 메시지 해석 | "이 에러를 수정해줘" |
| **속도** | 숙련도에 비례 | 프롬프트 품질에 비례 |

### 1.4 Vibe Coding은 코딩을 대체하는가?

**아닙니다.** Vibe Coding은 기존 개발을 보완하는 방식입니다:

- **프로토타이핑**: 아이디어를 빠르게 검증할 때 강력
- **반복 작업**: 보일러플레이트 코드, CRUD API 등 자동화에 적합
- **학습 보조**: 새로운 언어나 프레임워크를 배울 때 가이드 역할
- **코드 리뷰**: 기존 코드의 개선점을 파악하는 데 활용

다음에는 여전히 전통적 코딩 역량이 중요합니다:

- **아키텍처 설계**: 시스템 전체 구조는 개발자가 결정
- **성능 최적화**: 병목 지점 파악과 튜닝
- **보안 검토**: AI가 놓칠 수 있는 보안 취약점 검수
- **복잡한 버그 디버깅**: 깊은 맥락 이해가 필요한 문제

## Part 2: Vibe Coding 실전 도구

### 2.1 대표적인 도구들

Vibe Coding을 실천하려면 AI 코딩 도구가 필요합니다. 2025-2026년 현재 주요 도구를 비교해봅니다.

| 도구 | 형태 | 특징 | 추천 대상 |
|------|------|------|-----------|
| **Claude Code** | CLI (터미널) | 전체 리포지토리 이해, 자율적 코딩 에이전트 | 터미널 친화적 개발자 |
| **Cursor** | IDE | VS Code 기반, 인라인 AI 편집 | IDE 선호 개발자 |
| **GitHub Copilot** | IDE 플러그인 | 코드 자동완성, 채팅, 에이전트 모드 | VS Code/JetBrains 사용자 |
| **Windsurf** | IDE | Cascade 플로우, 다중 스텝 추론 | 실험적 기능 선호 |
| **Aider** | CLI | 오픈소스, 다중 LLM 지원 | 오픈소스 선호 개발자 |
| **v0** | 웹 | 텍스트 → React UI 컴포넌트 생성 | 프론트엔드 프로토타이핑 |

### 2.2 Claude Code로 Vibe Coding하기

Claude Code는 터미널에서 동작하는 AI 코딩 에이전트입니다. Vibe Coding에 특히 적합한 이유는:

```
# 설치
npm install -g @anthropic-ai/claude-code

# 프로젝트 디렉토리로 이동 후 실행
cd my-project
claude
```

**실전 예시 — 프롬프트로 기능 추가하기:**

```
> 사용자 인증 기능을 추가해줘. JWT 토큰을 사용하고,
  로그인, 로그아웃, 회원가입 API가 필요해.
  Express.js와 TypeScript를 사용하고 있어.
```

Claude Code가 알아서:
1. 필요한 파일들을 생성하고
2. 기존 코드와 통합하고
3. 의존성을 설치하고
4. 테스트까지 작성합니다

### 2.3 Cursor로 Vibe Coding하기

Cursor는 VS Code를 기반으로 한 AI 전용 IDE입니다.

**핵심 기능:**

| 기능 | 단축키 | 설명 |
|------|--------|------|
| **Chat** | `Cmd+L` | AI와 대화하며 코드 질문 |
| **Edit** | `Cmd+K` | 선택한 코드를 AI가 수정 |
| **Composer** | `Cmd+I` | 여러 파일에 걸쳐 코드 생성 |

**실전 예시 — Composer로 기능 구현:**

1. `Cmd+I`로 Composer 열기
2. 프롬프트 입력: "이 컴포넌트에 다크모드 토글을 추가해줘. 사용자 설정은 localStorage에 저장해"
3. AI가 여러 파일을 동시에 수정하는 변경사항 제안
4. `Accept` 또는 `Reject`로 각 변경 수락/거부

### 2.4 도구 선택 가이드

```
어떤 도구를 선택할까?

터미널을 주로 사용한다 ───→ Claude Code
                            │
IDE를 주로 사용한다 ───────→ Cursor 또는 Copilot
                            │
오픈소스를 선호한다 ───────→ Aider
                            │
UI를 빠르게 만들고 싶다 ──→ v0
```

## Part 3: 효과적인 프롬프트 작성법

Vibe Coding의 핵심은 **프롬프트 품질**입니다. 좋은 프롬프트가 좋은 코드를 만듭니다.

### 3.1 좋은 프롬프트의 구조

```
[컨텍스트] + [구체적 요청] + [제약사항]
```

#### 나쁜 예:

```
로그인 만들어줘
```

#### 좋은 예:

```
Next.js App Router 프로젝트에 소셜 로그인을 추가해줘.
Google과 GitHub OAuth를 지원하고,
NextAuth.js v5를 사용해줘.
로그인 후에는 /dashboard로 리다이렉트하고,
세션은 JWT로 관리해줘.
```

### 3.2 프롬프트 작성 5원칙

#### 1. 구체적으로 작성하라

```
❌ "버그 고쳐줘"
✅ "사용자가 로그인 후 새로고침하면 401 에러가 발생해.
    아마 토큰 갱신 로직의 문제인 것 같아. 확인해줘."
```

#### 2. 컨텍스트를 제공하라

```
❌ "테스트 추가해줘"
✅ "UserService의 createUser 메서드에 대한 단위 테스트를 작성해줘.
    정상 케이스, 중복 이메일 케이스, 유효하지 않은 입력 케이스를
    모두 커버해줘. Jest를 사용하고 있어."
```

#### 3. 기술 스택을 명시하라

```
❌ "API 만들어줘"
✅ "Spring Boot 3.2 + Kotlin으로 REST API를 만들어줘.
    JPA로 데이터베이스는 PostgreSQL을 사용하고,
    응답은 ResponseEntity로 감싸줘."
```

#### 4. 반복적으로 개선하라

Vibe Coding은 한 번에 완벽한 코드를 얻는 것이 아닙니다. 대화를 통해 점진적으로 개선합니다:

```
[1차] "사용자 목록 페이지를 만들어줘"
      → 기본 테이블 생성

[2차] "페이지네이션을 추가하고, 정렬 기능도 넣어줘"
      → 기능 개선

[3차] "모바일에서도 잘 보이도록 반응형으로 만들어줘"
      → 반응형 적용

[4차] "로딩 상태와 에러 처리도 추가해줘"
      → UX 개선
```

#### 5. 코드를 리뷰하라

AI가 생성한 코드를 무비판적으로 수용하지 마세요:

```
"생성된 코드를 리뷰해줘. 특히 다음을 확인해줘:
 - SQL 인젝션 방어가 되어있는지
 - 에러 핸들링이 적절한지
 - 메모리 누수 가능성이 없는지"
```

## Part 4: 실전 Vibe Coding 워크플로우

### 4.1 프로젝트 시작하기

새 프로젝트를 Vibe Coding으로 시작하는 과정입니다:

```
Step 1: 아이디어를 자연어로 설명
──────────────────────────────────
"Todo 앱을 만들고 싶어.
 할 일 추가, 완료 처리, 삭제 기능이 필요하고,
 카테고리별로 필터링할 수 있어야 해.
 React + TypeScript + Tailwind CSS를 사용해줘."

Step 2: AI가 초기 구조 생성
──────────────────────────────────
→ 컴포넌트 구조
→ 상태 관리
→ 스타일링
→ 기본 CRUD 로직

Step 3: 반복 개선
──────────────────────────────────
"localStorage에 데이터를 저장하게 해줘"
"드래그앤드롭으로 순서를 바꿀 수 있게 해줘"
"다크모드를 지원해줘"

Step 4: 품질 개선
──────────────────────────────────
"테스트 코드를 작성해줘"
"성능을 최적화해줘"
"접근성(a11y)을 개선해줘"
```

### 4.2 기존 프로젝트에 기능 추가하기

```
Step 1: 변경 범위 설명
──────────────────────────────────
"이 프로젝트의 src/api/user.ts 파일에
 비밀번호 재설정 기능을 추가해줘.
 이메일로 재설정 링크를 보내는 방식이야."

Step 2: 관련 파일 파악
──────────────────────────────────
AI가 자동으로:
- 관련 컨트롤러, 서비스, 리포지토리 식별
- 데이터베이스 마이그레이션 필요 여부 판단
- 영향받는 테스트 파일 탐지

Step 3: 코드 생성 및 통합
──────────────────────────────────
- 기존 패턴과 스타일에 맞게 코드 생성
- 필요한 임포트와 의존성 자동 추가

Step 4: 검증
──────────────────────────────────
"생성된 코드가 기존 코드와 잘 통합되는지 확인해줘.
 타입 에러가 없는지도 체크해줘."
```

### 4.3 디버깅 with Vibe Coding

```
Step 1: 에러 공유
──────────────────────────────────
"이 에러가 발생해:
 TypeError: Cannot read properties of undefined (reading 'map')
 at UserList.tsx:23:15

 UserList 컴포넌트에서 users.map()을 호출할 때
 users가 undefined인 것 같아."

Step 2: AI가 원인 분석
──────────────────────────────────
→ API 응답 구조 불일치 식별
→ null 체크 누락 발견
→ 로딩 상태 처리 부재 확인

Step 3: 수정 제안
──────────────────────────────────
→ 옵셔널 체이닝 적용
→ 기본값 설정
→ 로딩/에러 상태 UI 추가
```

## Part 5: Vibe Coding 모범 사례와 주의점

### 5.1 해야 할 것 (Do's)

| 항목 | 설명 |
|------|------|
| **작은 단위로 요청** | 한 번에 너무 많은 것을 요청하지 마세요 |
| **생성 코드 이해** | AI가 작성한 코드를 반드시 읽고 이해하세요 |
| **버전 관리 활용** | Git을 사용해 AI의 변경사항을 쉽게 되돌릴 수 있게 하세요 |
| **보안 검토** | API 키, 비밀번호 등이 코드에 노출되지 않았는지 확인하세요 |
| **테스트 작성** | AI가 생성한 코드에 대한 테스트를 반드시 작성하세요 |

### 5.2 하지 말아야 할 것 (Don'ts)

| 항목 | 설명 |
|------|------|
| **맹목적 수용** | AI 코드를 검토 없이 사용하지 마세요 |
| **보안 무시** | AI가 하드코딩된 시크릿을 넣을 수 있습니다 |
| **과도한 의존** | 기본기 없이 AI에만 의존하면 위험합니다 |
| **복잡한 아키텍처 위임** | 시스템 설계 결정은 개발자가 내려야 합니다 |
| **프로덕션 직행** | AI 코드는 반드시 리뷰 후 프로덕션에 반영하세요 |

### 5.3 생산성 팁

#### Git을 안전망으로 활용

```bash
# AI 작업 전 항상 커밋
git add . && git commit -m "before AI changes"

# AI가 변경한 내용이 마음에 들지 않으면
git checkout .
# 또는
git stash
```

#### CLAUDE.md 활용

프로젝트 루트에 `CLAUDE.md` 파일을 만들면, Claude Code가 프로젝트 컨텍스트를 항상 참조합니다:

```markdown
# 프로젝트 컨벤션
- TypeScript strict mode 사용
- 테스트는 vitest로 작성
- 컴포넌트는 함수형으로만 작성
- CSS는 Tailwind 사용
```

#### .cursorrules 활용

Cursor에서도 프로젝트 규칙 파일을 지원합니다:

```markdown
# .cursorrules
- 한국어 주석 사용
- 에러 처리는 반드시 포함
- 모든 함수에 JSDoc 작성
```

### 6.1 발전 방향

| 시기 | 예상 발전 |

### 6.2 개발자의 역할 변화

Vibe Coding 시대의 개발자는 다음 역량이 더 중요해집니다:

1. **문제 정의 능력**: 무엇을 만들지 명확히 설명하는 능력
2. **아키텍처 설계**: 시스템 구조를 결정하는 능력
3. **코드 리뷰**: AI가 생성한 코드의 품질을 평가하는 능력
4. **보안 의식**: AI가 놓칠 수 있는 보안 이슈를 파악하는 능력
5. **테스트 설계**: 무엇을 테스트해야 하는지 아는 능력

## 요약

Vibe Coding의 핵심을 한눈에 정리합니다:

